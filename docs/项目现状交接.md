## 4. 现有代码地图与测试注意点

```text
lib/main.dart                         打开DB，构建仓库并注入ProviderScope
lib/app/                              app、theme、buildAppRouter路由工厂
lib/core/config/platform_config.dart  assets平台配置读取
lib/core/webview/                     登录提示检测
lib/features/pickup/domain/           模型、平台枚举、仓库接口
lib/features/pickup/data/             SQLite仓库、H5同步服务
lib/features/pickup/presentation/     列表、详情、录入及Riverpod控制器
lib/features/auth/                    登录态仓库和身份码WebView
lib/features/settings/                配置展示、退出、清空已取
```

- repositoryProvider 保留抽象接口；widget 测试使用 `test/helpers/memory_pickup_code_repository.dart`，避免 FakeAsync 与 sqlite_ffi 原生事件端口挂起。
- 仓库／迁移测试用真实 SQLite FFI，不能用 widget 内存实现代替；两种仓库合并语义须一致。
- buildAppRouter 保留工厂，不恢复全局单例路由，避免测试间导航状态泄漏。
- 平台枚举为 PickupPlatform，避免与 dart:io Platform 同名。
- Cookie API 为 `WebViewCookieManager().clearCookies()`；登录态留在系统 WebView 沙箱，不复制 Cookie 到普通存储。
- URL 与选择器以 `assets/platform_config.json` 为准；阶段0文档只是历史来源，不将示例 URL 当成有效地址。

## 6. 执行顺序与阶段出口

| 阶段 | 开发起点与出口 |
| --- | --- |
| M0 | 先确认SDK路径；按M0-A/B/C/D修复基础问题，重跑analyze/test，构建release验证 |
| M1 | 候选／来源模型 → 版本迁移 → Dart解析与语料 → 事件幂等合并 → 粘贴预览／待确认／历史 |
| M2 | Kotlin持久队列 → 通知提取／白名单 → Dart提交后ack → 权限状态和进程恢复矩阵 |
| M3 | 可选短信、规则试解析、地址分组、备注分享、官方App身份码入口 |
| M4 | 标准小组件、快照、大字／暗色；独立验证后台Flutter入口，失败保留前台恢复处理 |
| M5 | JSON归一化等同步修复，用户登录后实测DOM；只启用实际验证通过的平台 |

完整任务包及每包验收见设计第8节。每个实现提交最多3文件（含测试），较大的任务包先拆契约、实现、接线和验收。每次完成后更新本交接文档的真实状态，不一次实现整条链路。

首个可用版本出口为 M0—M2：无需登录或短信权限也可用本地功能；通知已送达的候选先可靠暂存，恢复App后处理。不承诺 M2 已经支持 App 关闭时自动解析和实时更新小组件。

后续数据升级必须保留旧ID／已取状态／取件时间；不能通过删除数据库解决迁移失败。主库只由Dart管理，Kotlin只写候选队列，避免双端维护业务表。
