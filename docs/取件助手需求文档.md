# 取件助手需求规格说明书

> 更新日期：2026-10-19。本文为 Parcel＋ExpressAssistant 双参考设计的需求基线；所有“计划”均未实现。
> 技术方案与任务编号见 [设计与实施计划](取件助手设计文档.md)，实际状态见 [交接文档](项目现状交接.md)。

## 1. 产品定位与路线

取件助手面向经常取快递的个人用户，将分散在短信、App 通知和复制文本中的取件码汇总为本地清单，按取件点查看、标记已取，并快捷打开官方身份码入口。

参考 [Parcel](https://github.com/shareven/parcel) 的本地解析、地址分组、自定义规则和桌面卡片体验，同时借鉴 [ExpressAssistant](https://github.com/Halo0sama/ExpressAssistant) 的 WebView 登录配置、同步协调、渠道报告与保留用户字段的做法，保留 Flutter + Riverpod + SQLite 架构。

本地主线仍为“文本导入 → 通知识别 → 可选短信识别”。登录可靠性在 M0 修复，统一来源与刷新底座提前到 M1，以 fake 适配器验证；真实平台取件信息在 M5 独立接入，默认 WebView 内读取，HTTP／SSR 方案只作专项比较。网络不可用或账号未登录不影响本地功能，不扩展为完整物流追踪产品。

产品以 Android 8.0+ 为主要验收平台。iOS 保留手动录入、粘贴解析、列表、历史和可用的身份码入口；不承诺读取系统短信或其他 App 通知。iOS 部署下限以实际 Flutter SDK 与插件构建验证为准。

## 3. 用户流程与页面

1. 首次打开直接进入本地待取列表；不强制登录、不强制授权。
2. 点击“导入文本”，主动粘贴短信／复制内容，预览识别结果，补齐地址后保存；也可继续使用手动表单。
3. 在“来源与权限”中自愿开启通知监听，逐个选择来源 App；短信读取另行开启。
4. 接收到的候选按同一解析规则处理，完整结果自动入库，缺地址或存在歧义的结果进入“待确认”。
5. 首页按取件点分组，展示待取数量、柜号、格口和大号取件码；支持复制、备注、分享、标记已取。
6. 已取记录进入历史，可恢复；删除和清空历史需确认。重复采集不得自动恢复已取记录。
7. 身份码按钮显示“应用内查看”与“打开官方 App”；跳转失败明确提示可用的替代入口。
8. 点击刷新立即展示本地清单，再分批补入可用来源；每个来源分别显示成功、部分成功、需登录或失败及最后成功时间。一个平台失败不遮蔽其他来源，也不把旧记录当作本次新结果。

计划页面：待取首页、取件详情、手动录入／文本导入、待确认、历史、规则管理及试解析、地址分组、来源与权限、设置。刷新结果和会话状态嵌入首页／来源页，不为技术契约新增面向用户的复杂配置页。初期复用现有页面逐步增加入口，不一次重建全部导航。

## 4. 功能与交付优先级

| 编号 | 功能 | 要求 | 交付阶段 |
| --- | --- | --- | --- |
| R01 | 本地基础可靠性 | 稳定记录 ID；重复写入保留已取时间、备注和用户修正；错误可恢复 | M0 |
| R02 | 文本导入 | 主动粘贴后预览，支持多个取件码逐条确认，不后台读取剪贴板 | M1 |
| R03 | 规则解析 | 提取取件码、地址、柜号、格口；支持中文柜号、横杠变体；拒绝将验证码、电话、费用等误作取件码 | M1 |
| R04 | 待确认 | 有码缺地址、多地址歧义、字段冲突时保留候选，用户修正后转正式记录 | M1 |
| R05 | 历史与状态 | 待取／已取两态；手动恢复清空 pickedAt；来源消失或通知被划掉不等于已取 | M1 |
| R06 | 通知监听 | 仅处理用户启用的 App，可配置标题关键词；排除本 App 通知、汇总通知与空正文 | M2 |
| R07 | 后台接收边界 | M2 先可靠暂存，恢复 App 时解析；M4 再实现系统允许时的后台解析与小组件更新 | M2、M4 |
| R08 | 短信识别 | 新短信接收与历史读取分开授权；历史默认近 7 天，可选近 30 天；支持分段短信合并 | M3 |
| R09 | 自定义规则 | 支持码关键词、地址别名、忽略词；高级正则需校验、试运行，失败不影响其他规则 | M3 |
| R10 | 地址分组 | 将多个地址别名归入同一标签；只改变展示，不改变真实地址和记录去重身份 | M3 |
| R11 | 快捷操作 | 复制码、编辑备注、主动分享文本；分享前可预览，默认不含来源消息全文 | M3 |
| R12 | 身份码入口 | 保留官方 H5；借鉴 Parcel 的官方 App 跳转；未安装、深链失效、登录过期均有提示 | M0、M3 |
| R13 | 桌面小组件 | 先提供一种标准尺寸，显示待取数／地址／码；点击进入详情；大字与暗色适配 | M4 |
| R14 | 平台取件信息 | 默认WebView内DOM／页面已有数据读取，经真机验证才开启；结构化结果与文本共用合并流程 | M5 可选 |
| R15 | 会话状态 | 区分未知、未登录、已登录及过期；普通查看不清其他会话，退出／切换后旧请求不得继续写入 | M0、M5 |
| R16 | 统一刷新与结果 | 同轮刷新互斥附着，来源独立超时／取消／结果报告，分批展示；合法零条与失败分开，重复不计新增 | M1底座、M2/M5接入 |
| R17 | 获取路径研究 | 固定ExpressAssistant源码比较WebView内读取与Cookie签名HTTP／SSR，输出可采用或不采用的证据结论；不代表实现或默认启用 | M5-C |

不纳入当前计划：快递物流轨迹、寄件、快递100取件码接口、OCR／无障碍截屏、云端 AI、账号密码托管、厂商专属小组件及强制常驻保活。

只接入取件所需的最小字段，不因ExpressAssistant具备物流、商品和多账号功能就同步扩大范围。首个平台只验证一个账号；预留来源／会话作用域不等于已支持多账号隔离。平台物流“已签收／交易完成”不能自动把本地记录改为已取件。

## 5. 来源、权限与隐私

- “来源”表示手动、粘贴、通知、短信或 H5；“平台”表示淘宝、菜鸟等，无法确定的平台显示“未知”，不可默认归为淘宝。
- 各来源独立开关。通知使用权与应用发送通知权限分别显示；未授予发送通知权限也能导入和查看记录。
- 首次启用前解释用途，拒绝或撤销后停止对应采集，本地清单继续可用。微信只读取已授权且实际展示的通知，不读取聊天数据库，不承诺恢复折叠／隐藏的正文。
- 本地解析离线可用；现有 H5 身份码需要联网，因此不照搬 Parcel 的“应用完全不联网”描述。
- 通知先在包名白名单过滤，再保存最小候选。短信候选只保留具有取件语义的内容，不保存整份短信收件箱。
- 成功处理后清除原文，只保存结构化字段和去重标识；失败候选原文默认最多保留 7 天、500 条，可提前清空。详情明确提示原文到期不可恢复。
- 日志记录来源类型、错误码与计数，不记录验证码、手机号、Cookie 或通知／短信原文；删除记录同步清理关联候选及小组件内容。
- 登录由用户在官方页面完成，Cookie 留在 WebView 沙箱，不导出复制；身份码只展示或跳转，不截图缓存、不解析入库。
- ExpressAssistant 的Cookie导出、签名HTTP与SSR只作为M5研究对象，当前正式设计仍维持上一条会话边界；若研究结论选择外导路径，先补安全存储、生命周期、撤销、备份排除及测试的独立设计，不把普通偏好文件存Cookie直接移植过来。
- sessionRef是本地关联标识而非凭证；仅有会话特征不代表服务器确认登录成功。退出不删除取件记录，未经核实的账号不回退使用其他已登录账号。

## 6. 验收标准

### 6.1 自动化与真机用例

以下为计划用例，尚不存在的测试文件不可作为当前已通过证据。

| 场景 | 自动化要求 | Android 真机验收 |
| --- | --- | --- |
| 旧数据升级 | v1 数据迁移后数量、ID、已取时间、可选字段一致 | 覆盖安装保留原待取与历史 |
| 重复与状态 | 同一事件重放不新增；跨来源重复不清空用户字段；已取不复活；新包裹复用旧码可新增 | 连续刷新、杀进程后重开 |
| 解析 | 至少 60 条脱敏正例、40 条反例；覆盖多码、柜号、格口、未知平台、缺地址 | 粘贴预览与手动修正 |
| 通知 | mock 标准／长文本／消息样式、空／折叠／重复／更新通知，断线与重连 | 前台、后台、划掉进程、强行停止、重启分别记录 |
| 短信 | mock 权限拒绝、撤销、历史重扫、分段短信、广播与收件箱重复 | 接收测试短信；网络短信无法读取时提示通知／粘贴方案 |
| 规则与分组 | 正则错误隔离；试解析无写入；别名不改变去重键；大字布局可用 | 添加规则、修改分组、系统字体放大 |
| 小组件 | 快照版本、已取／删除／待确认不泄露、过期提示 | 新事件、取件、删除、重启后显示一致 |
| 身份码 | 导航与错误处理 mock、第三方 Cookie 配置检查 | release 联网、跨域登录、会话保持、退出、官方 App 跳转 |
| 刷新协调 | fake来源覆盖同时刷新、迟到批次、合法空结果、部分成功、一个来源失败、总超时／取消 | 本地列表先可用，已提交批次先显示；界面报告新增／重复／待确认及需登录来源 |
| 平台字段与作用域 | 结构化字段完整性、同订单多包裹、跨账号同码／运单号、来源状态与已取状态分离 | 单账号连续3轮刷新无重复，切换／退出后旧请求不入库 |
| 平台路径研究 | 脱敏fixture检查SSR／DOM字段映射，不生成虚假取件码，不把参考接口当已通过证据 | 用本人账号确认实际取件字段、分页、过期与退出；不能通过时记录回退到官方入口 |

每个代码任务完成后执行 `flutter analyze` 与 `flutter test`；涉及 Kotlin 的任务增加对应原生测试／构建，平台通道使用 mock 加真机验收。现有 widget 测试继续注入内存仓库，不能代替真实 SQLite 的迁移与去重测试。

### 6.2 可测量目标

- 本地清单冷启动目标 3 秒内可操作，不等待 H5 网络请求。
- 前台刷新每来源总预算初始10秒、整轮30秒；共享WebView会话串行、独立会话最多两个并发，预算内允许部分成功并可取消，不把超时包装成空结果成功。
- 单条不超过 4 KB 的文本解析目标 100 ms 内；历史导入分批进行，展示进度并可取消。
- 在 1,000 条本地记录下，分组、筛选、标记已取不阻塞主界面。
- 后台任务允许系统延后；不得将“收到通知后立即刷新小组件”写成可靠性承诺。
- H5 显示加载、超时与重试状态；不再承诺平台页面 2 秒内加载或网络同步固定 5 秒完成。

在同一台 Android 真机记录系统版本、App 版本、数据量和至少 5 次测量结果；厂商后台限制单列说明。

## 7. 版本出口

- **首个可用版本（M0—M2）**：无登录可用，文本导入／待确认／历史完整，统一刷新和来源报告已接本地队列，通知可可靠暂存并在恢复App后导入，旧数据升级无损；不要求真实平台抓取通过。
- **Parcel 体验对齐版（M3—M4）**：补齐可选短信、规则管理、地址分组、备注分享、大字模式与标准小组件；后台能力通过真机矩阵再开放。
- **平台扩展版（M5）**：完成A/B/C路径比较，只将通过验收的来源接入统一协调器；默认A为WebView内读取、C为官方入口／文本导入回退，B为Cookie签名HTTP研究。未通过保持关闭，研究完成与功能上线分别记录。

任务依赖、测试清单及回退策略以 [设计文档第 8 节](取件助手设计文档.md#8-实施计划) 为准。
